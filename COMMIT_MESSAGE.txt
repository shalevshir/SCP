fix: HTF structure label extraction in streaming mode

Root Causes:
1. Fixed-Index Bug: The StreamingFeatureProcessor was using a fixed index to
   extract structure labels from the sparse labels series. Since structure
   labels only exist at actual swing points (not every bar), this fixed index
   often landed on non-swing bars with pd.NA, preventing label updates.

2. Insufficient Buffer Size: Even after fixing extraction, 1H timeframe had
   a 30-bar buffer (only 30 hours), which was too small to capture enough
   swing points for reliable structure detection.

Solutions:
1. Changed extraction logic to find the most recent valid (non-NA) swing point
   using dropna().iloc[-1] instead of a fixed index calculation.
   
2. Made buffer size timeframe-aware with a new _get_buffer_size_for_timeframe()
   method:
   - 1H: 100 bars (~4 days of data)
   - 15M: 50 bars (~12.5 hours)
   - 1M: 30 bars (30 minutes)
   
3. Added debug logging when no swings detected to help diagnose buffer issues.

Impact:
- HTF structure labels now populate correctly in streaming mode
- Structure-based bias calculations are now functional
- All backtests using streaming HTF now have complete structure data
- No impact on vectorized HTF (continues to work as before)
